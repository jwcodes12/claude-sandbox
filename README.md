# Claude Sandbox

Monorepo for personal vibecode sites and prototypes. The point of this repo is to keep experiments in one place so agents can add a new app without creating another GitHub repository.

## Layout

```txt
apps/
  agi-markets/      Existing Next.js market dashboard
  tech-radar/       Static RSS/Twitter-driven news radar generated by OCI
ops/
  systemd/          User-level OCI service/timer templates
  deploy/           OCI install helpers
```

Each app should be self-contained: its own `package.json`, framework config, deploy config, and static assets. Shared code can be added later under `packages/` once there is real duplication.

## Commands

```bash
npm install
npm run dev
npm run build
npm run lint
npm run worker:force -w @claude-sandbox/tech-radar
```

The default `dev` command runs `apps/agi-markets`. App-specific scripts use npm workspaces:

```bash
npm run dev -w @claude-sandbox/agi-markets
npm run build -w @claude-sandbox/agi-markets
npm run dev -w @claude-sandbox/tech-radar
npm run worker:force -w @claude-sandbox/tech-radar
```

## Adding Apps

Add new ideas under `apps/<short-name>`. Prefer boring names that explain the site, for example `apps/news-radar` or `apps/receipt-splitter`.

For deploys:

- Netlify: create one Netlify site per app and set the base directory to that app folder.
- Vercel: create one Vercel project per app and set the root directory to that app folder.
- Static apps: keep generated output inside the app, usually `public/` or `dist/`.

The OCI box can run scheduled workers that update generated static files and deploy a single app directory without changing the rest of the monorepo.

## Tech Radar Workflow

`apps/tech-radar` is designed as a static site with a worker:

1. OCI runs the worker every 15 minutes via `systemd`.
2. The worker fetches RSS/Twitter bridge feeds from `feeds.yaml`.
3. Items are cached in SQLite, clustered, ranked, and turned into topic JSON.
4. Deterministic briefs are always generated; model briefs are opt-in.
5. `public/` is deployed to Netlify by default, with Vercel as a fallback.

Claude Code and Codex CLI can be used on OCI for manual research passes and maintenance, but the recurring worker should stay deterministic and non-interactive.
